## 페이지 1

BreachScope 시스템 아키텍처 기획 및 설계 연구
BreachScope는 다양한 계층의 디지털 포렌식 로그를 자동 수집/정규화하고, 시간 기반 상관분석과 시나리오 기반 추
론을 통해 침해 사고의 흐름을 재구성하는 것을 목표로 합니다. 또한 악성 명령어의 복호화와 최종 행위 식별을 수행한
후 HTML/PDF 보고서를 자동 생성하며, 오프라인 환경에서도 동작할 수 있어야 하고, 90% 이상의 정확도를 지향합니
다. 이러한 목표를 달성하기 위해, 유사 시스템의 사례와 디지털 포렌식 자동화 도구의 핵심 구성 요소, 시나리오 기반
상관 분석 기법, 자동 보고서 생성 방법, 오프라인 실행 및 보안 고려사항을 조사하였습니다.
유사 시스템 사례 분석: Velociraptor, KAPE, Timesketch
Velociraptor:  Velociraptor는 Rapid7에서 개발한 오픈소스 DFIR 플랫폼으로, 클라이언트-서버 모델 아키텍처를 기
반으로 동작합니다. 경량 에이전트를 각 엔드포인트에 설치하고 중앙 서버에서 이를 관리하며, Velociraptor Query
Language (VQL)라는 특화된 질의 언어를 사용해 다양한 포렌식 아티팩트를 실시간 조회 및 수집합니다. 이 플랫폼은
중앙 서버(Velociraptor Server) 와 엔드포인트 에이전트(Velociraptor Client) 로 구성되며, 서버 측에서 엔드포인
트 메타데이터 대시보드, 아티팩트 저장소, 실시간 VQL 질의 실행, 검색 가능한 포렌식 이력, 통합 파일 브라우저와 레지
스트리 뷰어, 이벤트 모니터링 및 알림 등의 기능을 제공합니다. 클라이언트 에이전트는 Windows, Linux, macOS에
서 동작하는 경량 바이너리로, 서버와의 암호화 통신을 통해 명령을 대기합니다. 에이전트는 평상시 CPU 1% 미만을 사
용할 정도로 경량으로 설계되어 구형 시스템에서도 구동 가능하며, 명령 수신 시 VQL 기반의 포렌식 스캔을 실행하여
로그, 레지스트리 키, 파일 메타데이터 등의 아티팩트를 수집하고 프로세스 생성이나 네트워크 연결 이벤트 스트림을 전
송하며, 파일/레지스트리 변경 모니터링이나 백그라운드 예약 수집 작업도 수행할 수 있습니다. Velociraptor의 강점은
다양한 아티팩트 정의 모음과 VQL을 통해 수집 절차를 유연하게 커스터마이즈할 수 있다는 점입니다. Windows 이벤
트 로그, Prefetch, ShimCache/AmCache, 브라우저 기록, 시작 프로그램 및 스케줄 작업, 파일 시스템 메타데이터,
사용자 로그인 이력, 레지스트리 주요 키 등 방대한 범위의 아티팩트 수집 스크립트가 기본 내장되어 있으며, 조직 환경
에 맞게 커스텀 아티팩트를 작성하여 팀 내 공유 및 버전 관리할 수도 있습니다. 또한 Velociraptor는 Sigma 규칙을 통
합하여 Windows 이벤트 등의 실시간 모니터링 시 의심 이벤트를 탐지하고 경고하는 탐지 엔진 으로 활용할 수도 있습
니다.
Velociraptor는 오프라인 수집기(Offline Collector)  기능을 통해 네트워크 연결이 제한된 환경에서도 활용할 수 있
습니다. 오프라인 수집기는 미리 선택된 아티팩트와 파라미터로 구성된 독립 실행형 바이너리로, 에이전트를 설치하지
못하는 격리환경에서 실행하여 증거를 수집할 수 있습니다. 대상 시스템에서 오프라인 수집기를 실행하면 지정된 아티
팩트를 모두 수집하여 암호화된 아카이브(zip) 파일로 패키징하며, 이 파일을 가져와 Velociraptor 서버에  가져오기
(import)  하면 수집 내용이 해독되어 분석에 활용됩니다. 이 방식은 네트워크 없이 독립적으로 동작 하고 수집 결과를
안전하게 암호화(패스워드, X.509 인증서 또는 PGP 활용) 하며, 필요한 경우 서드파티 포렌식 도구도 포함시켜 실행할
수 있게 설계되었습니다. 이러한 오프라인 모드는 공공기관, 중요 기반시설 같이 폐쇄망 환경이나, 침해사고로 네트워크
가 격리된 시스템에서 증거를 수집해야 하는 시나리오에 특히 유용합니다. Velociraptor 사례를 통해 BreachScope에
서는 에이전트 기반 원격 수집 , 중앙화 서버를 통한 오케스트레이션 , 유연한 쿼리 언어(VQL)와 탐지 규칙(Sigma) 지
원, 오프라인 수집기 제공  등의 아키텍처 요소를 참고할 수 있습니다.
KAPE (Kroll Artifact Parser and Extractor):  KAPE는 Kroll사에서 개발한 고속 디지털 포렌식 수집 도구로, 트라
이애지(초동 포렌식) 에 특화된 설계입니다. KAPE는 클라이언트-서버 구조가 아니라 단일 실행 파일 형태로 구동되며,
두 개의 주요 단계로 이루어집니다: 대상(Target) 수집  단계와 모듈(Module) 실행  단계입니다. Target은 수집해야 할
파일 및 디렉터리 경로들의 모음으로서, KAPE 실행 시 지정된 대상 위치에서 포렌식 가치가 높은 다양한 파일들을 신속
히 찾아내어 복사합니다. 이어서 Module 단계에서는 미리 정의된 외부 프로그램이나 스크립트를 실행하여, Target 단
계에서 수집된 파일들을 자동으로 파싱/분석 하거나 추가 처리를 수행합니다. 예를 들어, Registry Hive 파일을 수집한
후 Registry 데이터베이스를 CSV로 변환하는 모듈을 실행하거나, 이벤트 로그(.evtx) 파일을 읽어 추출된 이벤트 레코
드로 변환하는 스크립트를 돌리는 식입니다. KAPE에는 60개 이상의 사전 정의된 Target 프로파일과 90개 이상의 모듈
이 내장되어 있어, 일반적인 포렌식 조사에 필요한 수집 및 1차 분석 작업 대부분을 커버합니다.

## 페이지 2

KAPE의  또  다른  특징은  아티팩트  분류  수집 입니다.  수집한  증거  파일들을  EvidenceOfExecution,
BrowserHistory, AccountUsage  등 논리적인 카테고리별 디렉터리 구조로 정리하여 저장함으로써, 조사관이 개별
아티팩트의  처리  방법을  몰라도  카테고리별로  일목요연하게  살펴볼  수  있게  돕습니다.  예를  들어
“EvidenceOfExecution”(실행의 흔적) 디렉토리에는 Prefetch, ShimCache, Amcache, UserAssist 등 프로그램 실
행과 관련된 여러 아티팩트 파일들이 한곳에 모여 저장되므로, 조사관은 이 디렉토리만 집중적으로 분석하면 해당 시스
템에서 어떤 프로그램들이 실행되었는지를 쉽게 파악할 수 있습니다. 이처럼 카테고리별 그룹화 는 포렌식 프로세스의
표준화와 신속화 에 기여하여, 조사자가 일일이 어떤 아티팩트를 어디서 수집하고 어떻게 해석할지 고민하는 시간을 줄
여줍니다. KAPE 사례를 통해 BreachScope 기획 시 신속한 멀티-아티팩트 수집 엔진 과 모듈화된 자동 파서 연계  설계
의 중요성을 확인할 수 있습니다. 다만 KAPE 자체는 주로 증거 수집과 정리에 초점을 맞추고 있어, BreachScope에서
는 KAPE의 수집/모듈 개념을 참고하되 그 후단의 이벤트 상관분석 과 시나리오 추론  및 리포팅 기능을 추가로 설계해야
할 것입니다.
Timesketch:  Timesketch는 구글에서 오픈소스로 공개한 협업 타임라인 분석  도구로, 여러 소스에서 수집한 이벤트
들을 시간순으로 통합하여 대화식으로 분석할 수 있는 웹 기반 플랫폼입니다. Timesketch의 핵심 개념은  스케치
(sketch) 라는 단위로, 하나의 스케치가 하나의 사건(case)에 대응합니다. 각 스케치에는 여러 개의 타임라인을 추가할
수 있는데, 예컨대 한 사건 안에 “PC1의 Windows 이벤트 로그 타임라인”, “PC1의 웹 브라우저 기록 타임라인”, “메일
서버 로그 타임라인” 등을 개별적으로 불러온 뒤 이를 한 화면에서 겹쳐 보며 종합 분석할 수 있습니다. Timesketch는
Plaso(Log2Timeline) 등의 도구로 생성한 CSV/JSONL 타임라인 파일 또는 개별 이벤트 데이터를 업로드하여, 백엔드
Elasticsearch 데이터베이스에 이벤트들을 색인합니다. 이후 웹 GUI를 통해 키워드 검색, 필터링, 태그 달기, 코멘트 추
가 등의 기능을 제공하여 수많은 이벤트 중 의미 있는 항목을 빠르게 식별하고 탐색할 수 있습니다. 이러한 멀티소스 타
임라인 통합  및 인터랙티브 탐색  기능을 통해 분석가는 사건과 연관된 여러 시스템의 로그를 한데 모아 시간 순으로 보
면서 공격 흐름을 파악할 수 있습니다.
Timesketch의 자동 분석기(Analyzer)  기능은 BreachScope에 참고할 중요한 요소입니다. Analyzer는 미리 정의된
로직으로 타임라인 내 이벤트들을 처리하여 태그를 달거나 요약 정보를 생성하는 플러그인입니다. 예를 들어  Chain
Analyzer 는 서로 연관된 일련의 이벤트들을 “사슬(chain)” 형태로 자동 연결해 주는데, 웹 브라우저가 실행 파일을 다
운로드하고 이후 그 파일이 실행된 경우 두 이벤트를 한 흐름으로 묶어서 보여주는 식입니다. 이러한 체인 분석을 통해
사건의 인과관계가 드러나는 공격 시나리오 를 자동으로 식별할 수 있습니다 (예: 사용자가 웹에서 파일을 다운받고 곧바
로 해당 파일이 실행되어 악성 활동이 시작된 흐름). 이 밖에도 Windows EVTX 세션분석기(Sessionizer) 처럼 로그온
세션 ID나 사용자 계정별로 이벤트를 그룹화하여 각 세션 내 활동을 묶어주는 분석기나, Sigma Analyzer 처럼 알려진
침해지표 패턴(Sigma 규칙)을 타임라인 이벤트에 적용하여 의심 이벤트를 태그/주석 처리하는 기능도 있습니다. 한편
Timesketch는 대화형 UI 중심 도구이지만, 스토리(Stories)  기능을 통해 분석 결과를 서술형으로 정리하고 관련 증거
이벤트를 하이퍼링크로 참조하여 일종의 보고서 초안을 작성하는 기능도 제공합니다 (예: 공격 흐름을 글로 서술하면서,
근거가 되는 이벤트들을 링크로 달아주는 기능). Timesketch 사례는 BreachScope 설계 시 다중 소스 이벤트의 시간
축 통합,  자동화된 이벤트 연관 분석 모듈 ,  협업 및 해설 지원 기능 의  중요성을  시사합니다.  BreachScope는
Timesketch처럼 수집된 로그들을 공통 포맷의 타임라인으로 통합하고, 시나리오별 분석 로직(예: “웹 다운로드 → 실
행” 체인, “로그온 세션” 구분 등)을 통해 침해 흐름을 자동 재구성 하는 기능을 갖출 것으로 기대됩니다.
디지털 포렌식 자동화 도구의 필수 구성요소 및 데이터 흐름
디지털 포렌식 자동화 시스템을 설계하려면 전형적인 데이터 파이프라인의 각 단계를 고려해야 합니다:
데이터 수집 (Collection):  대상 시스템으로부터 다양한 계층의 로그와 아티팩트를 획득하는 단계입니다. 라이
브 시스템에서는 에이전트/수집 도구를 통해 Windows 이벤트 로그, 보안 감사 로그, Prefetch 파일, Registry
하이브, USB 연결 기록, Outlook 이메일 및 아카이브, 웹 브라우저 이력 등 필요한 모든 데이터를 가능한 신속
하게  수집해야  합니다.  Velociraptor처럼  중앙  서버가  에이전트를  원격  제어하여  수집하는  방식도  있고,
KAPE처럼 분석가가 대상 시스템에서 실행하여 로컬 수집을 수행하는 방식도 있습니다. 오프라인 디스크 이미
지나 메모리 덤프에 대해서는 Autopsy/Plaso 등 기존 도구를 통해 아티팩트를 추출할 수 있습니다. 속도와 효
율도 중요 고려사항인데, KAPE 사례에서 보듯 전체 디스크 이미징을 기다리는 대신 수분 내에 핵심 아티팩트만
선별 수집함으로써 시간 절약이 가능합니다. BreachScope는 미리 정의된 수집 프로파일 에 따라 다양한 계층•

## 페이지 3

의 아티팩트를 자동 수집하는 엔진을 포함해야 하며, 멀티 스레딩이나 비동기 수집을 통해 대용량 로그도 빠르
게 모을 수 있어야 합니다.
데이터 정규화 및 파싱 (Normalization/Parsing):  수집된 원시 로그들은 각각 포맷과 구조가 상이하므로, 이
를 공통된 스키마의 데이터로 변환하는 과정이 필요합니다. 예를 들어 Prefetch 파일은 실행 파일 경로와 마지
막 실행 시각을 포함하고, 레지스트리 Run 키는 특정 프로그램의 자동실행 설정을 나타내며, 이벤트 로그는 이
벤트 ID와 메시지 등의 필드로 구성됩니다. 이러한 이질적인 데이터를 표준화된 이벤트 객체 로 파싱하여, 최소
한 timestamp(시간), event_type(이벤트 유형), 그리고 관련 속성들(프로세스 이름, 파일 경로, 사용자 계정
등)을 갖춘 공통 형식으로 변환해야 합니다. 대표적으로 Plaso(log2timeline) 같은 도구는 수많은 포렌식 아티
팩트를 자동 파싱하여 통일된 타임라인 이벤트 리스트로 출력함으로써 이런 정규화 작업을 수행합니다 . 마
찬가지로 BreachScope도 내부적으로 각 로그 소스별 파서 모듈 을 가져야 하며, 예컨대 EVTX 파서는 이벤트
로그를 구조화된 레코드로 풀고, Prefetch 파서는 응용프로그램 실행 정보를 추출하며, 브라우저 기록 파서는
URL, 타임스탬프, 방문기록 등을 추출하는 식입니다. 이러한 파싱 결과는 공용 타임라인 데이터 모델로 통합되
어야 후속 분석이 가능하므로, 공통 필드 스키마 를 설계하고 각 파서가 이를 준수하도록 개발해야 합니다.
중앙 저장 및 색인 (Data Storage & Indexing):  정규화된 이벤트 데이터를 효율적으로 저장하고 조회할 수
있는 중앙 데이터 저장소가 필요합니다. 작은 규모에서는 SQLite 데이터베이스나 심지어 평문 JSON 파일로도
처리가 가능하겠지만, 수많은 호스트의 로그를 통합 분석하려면 Elasticsearch/OpenSearch와 같은 검색 지
향형 스토리지나 타임시리즈 DB를 고려해야 합니다. Timesketch는 백엔드로 Elasticsearch를 활용하여 수백
만 건의 이벤트도 거의 실시간에 가깝게 검색 및 필터링할 수 있도록 설계되어 있습니다. BreachScope에서는
오프라인 환경을 고려하여 클라우드 서비스에 의존하지 않고 로컬에 구축되는 인덱스 DB 를 사용해야 합니다.
이 DB는 시간으로 정렬된 이벤트 조회, 다중 필드 조건 검색, 상관관계 쿼리를 지원해야 합니다. 또한 수집된 원
본 증거 데이터(예: 원본 로그 파일이나 디스크 이미지)는 별도로 보관하고, 색인 DB에는 분석에 필요한 메타데
이터만 저장하는 이중화 전략이 필요합니다. 이 단계는 포렌식 타임라인의 토대 가 되는 부분으로, 저장소의 성
능과 확장성이 BreachScope 전체 성능을 좌우하게 됩니다.
시간 기반 상관분석 (Temporal Correlation Analysis):  저장된 이벤트들을 시간 순으로 정렬하여 사건의 전
개 흐름을 파악하는 것은 포렌식 분석의 기본입니다. BreachScope는 다양한 출처에서 모인 이벤트를 시간축
에 따라 통합한 후, 서로 인과관계나 연관성 을 띄는 이벤트들을 묶어내는 상관분석을 수행해야 합니다. 예를 들
어 USB 저장장치 연결 이벤트 발생 직후 해당 드라이브에서 실행 파일 생성 이벤트가 있었다면, 이것은 USB 장
치를 통한 악성코드 유입 시나리오로 연결 지을 수 있습니다. 또 어느 사용자의 로그인 이벤트 이후 그 사용자
계정으로 시스템 설정이 변경되거나 백도어가 설치됐다면, 해당 로그인 세션에서 악의적 활동이 일어난 것으로
추론할 수 있습니다. 이러한 분석을 자동화하기 위해 BreachScope는 이벤트 상관 규칙  내지 룰 엔진을 가져야
합니다. 규칙은 “만약 A 유형 이벤트 발생 후 일정 시간 내 B 유형 이벤트가 발생하면 두 이벤트를 연관짓는다”
또는 “동일한 프로세스 ID를 가진 이벤트들을 하나의 프로세스 활동으로 엮는다”와 같은 논리로 정의될 수 있습
니다. Timesketch의 Chain Analyzer처럼 공통 속성(예: 파일 해시나 경로)을 공유하거나 한 이벤트가 다른 이
벤트의 결과로 이어지는 경우 자동으로 체인으로 엮어주는 로직이 좋은 참고 사례입니다. 또 다른 예로 세션 기
반 상관은 Windows 보안 이벤트에서 로그온 세션 ID를 기준으로 그 세션에서 발생한 모든 이벤트(프로세스 실
행, 네트워크 접속 등)를 연결함으로써, 각 세션별 행위 흐름을 복원하는 방식입니다. BreachScope는 이렇게
시간 및 키 값 기반의 이벤트 연관  알고리즘을 통해, 산발적으로 보이는 로그 조각들을 하나의 사건 흐름으로 엮
는 기능을 구현해야 합니다.
시나리오 기반 추론 (Scenario-based Inference):  상관분석 결과 묶여진 이벤트들로부터 더 높은 수준의 공
격 시나리오를 도출하는 단계입니다. 시나리오 기반 추론이란 개별 이벤트의 나열을 넘어서 “무슨 일이 일어났
는가”를 재구성하는 것을 의미합니다 . 예를 들어 여러 로그 이벤트를 종합한 결과 “피싱 이메일 수신 → 사
용자가 첨부파일 실행 → 시스템에 백도어 설치 → 외부 서버와 C&C 통신”이라는 이야기 흐름이 보인다면, 이
것이 곧 하나의 침해 시나리오입니다. BreachScope는 이러한 공격 스토리라인 을 자동으로 인식하고 기술해줄
수 있어야 합니다. 이를 위해 알려진 공격 기법에 대한 플레이북(예: MITRE ATT&CK 시나리오)을 내장하거나,
과거 유사 사례의 패턴을 규칙화하여 적용할 수 있습니다. 하지만 시나리오 추론에는 불확실성이 따르므로, 여
러 가능한 가설을 두고 증거와 부합하지 않는 것을 배제해 나가는 시나리오 구축 및 정합성 평가  과정이 필요합

악성 명령어 복호화 및 행위 식별:  현대의 침해사고에서는 Powershell, WMI, 매크로 등 스크립트 기반 공격 이
빈번하며, 공격자들은 로깅을 피하기 위해 명령어를 난독화하거나 인코딩하는 경우가 많습니다. 예를 들어 이벤
트 로그에 Base64로 인코딩된 Powershell 명령이 기록되거나, 악성 워드 매크로가 난독화된 VBA 코드를 포함
하는 식입니다. BreachScope는 이러한 난독화/인코딩된 명령 을 자동으로 복원(디코딩/디스크램블)하여 그 실
제 의도를 파악하는 기능이 필요합니다. Powershell 명령어의 Base64 디코딩과 더불어, 일반 문자열 치환 난
독화 풀기, XOR/Rotaion 등의 간단한 암호 해제도 포함될 수 있습니다. 또한 레지스트리에 저장된 명령문(예:
Run 키의 값)이나 스크립트 파일 내 쉘코드 등도 분석 대상입니다. 복호화된 명령어에 대해서는 행위 식별 을 수
행해야 합니다. 가령 디코딩 결과가 Invoke-Mimikatz  같은 악성 도구 실행을 포함하면 “자격증명 탈취
행위”로 식별하고, 특정 IP로의 네트워크 통신 명령이 나오면 “외부 C2 통신 시도”로 태깅하는 식입니다. 이를
위해 BreachScope는 IOC(Indicators of Compromise) 패턴  및 MITRE ATT&CK 매핑  데이터베이스를 내
장하여, 특정 문자열이나 행동이 어떤 공격 기술(Technique)에 해당하는지 자동으로 분류할 수 있을 것입니다.
이러한 자동 행위 식별은 최종 보고서에 공격자의 최종 목적 또는 영향 을 기술하는 데도 활용됩니다 (예: “이 시
스템의 메모리 덤프가 외부로 유출되었습니다” 등).
자동 리포트 생성 및 요약 (Automated Reporting):  최종 단계에서는 BreachScope가 모든 분석 결과를 요
약하여 HTML/PDF 보고서  형태로 산출합니다. 보고서에는 전체 공격 타임라인 요약, 주요 공격 단계 설명, 발
견된 악성 파일/프로세스 목록, 관련 증거 (로그 경로, 이벤트 ID 등), 식별된 TTP(공격 기법) 요약, 대응 조치 권
고 등이 포함될 것입니다. 이 과정은 기존 수동 포렌식 보고서 작성에 드는 노력을 크게 절감시켜 주며, 특히 현
장 대응 시 신속한 초기 보고를 가능하게 합니다. 실제 사례로 Autopsy (The Sleuth Kit 기반 GUI) 도구는 조
사  결과를  요약한  보고서를  PDF  또는  HTML  형식 으로  생성하는  기능을  제공합니다.  상용  도구인
OSForensics 또한 케이스에 모은 모든 증거 아이템과 검색 결과를 표 형식으로 정리하고 하이퍼링크를 달아
서, 웹 브라우저에서 열람할 수 있는 HTML 보고서 나 PDF로 내보내기하는 기능이 있습니다. 이러한 보고서들
은 템플릿을 통해 항목의 포맷을 표준화하고, 사용자 로고 삽입이나 포함할 내용 선택 등의 커스터마이즈도 지
원합니다. BreachScope는 이러한 사례들을 참고하여, 미리 정의된 보고서 템플릿 (예: 요약 보고서, 상세 보고
서 등)을 갖추고 자동 생성된 내용을 사람이 읽기 쉬운 형태로 출력하도록 설계되어야 합니다.
PDF 및 HTML 기반 자동 보고서 생성 방식과 기술 스택
디지털 포렌식 도구에서 자동 보고서 생성 기능을 구현할 때 고려해야 할 기술적인 방법들과 스택은 다음과 같습니다:
HTML 템플릿 기반 보고서 생성:  분석 결과를 담은 데이터를 HTML로 렌더링하는 방식은 스타일링과 가독성
측면에서 유용합니다. BreachScope는 내부적으로 분석 결과를 구조화된 데이터(예: JSON 객체 목록)로 보유
하고 있을 것이므로, 이를 기반으로 Jinja2 같은 템플릿 엔진으로 HTML 문서를 생성할 수 있습니다. HTML 보
고서에서는 CSS를 사용해 표나 타임라인 다이어그램의 스타일을 꾸미고, 중요 내용은 굵게 혹은 색상 강조하
며, 이미지(예: 스크린샷)를 <img> 태그로 포함시킬 수 있습니다. JavaScript를 포함하면 보고서 내에서 인터
랙티브한 정렬/검색 기능이나 접힘/펼침 기능도 구현 가능합니다. 다만 보안상 외부 CDN이 아닌 로컬에 저장된
JS/CSS만 사용하고, 보고서 자체는 인터넷에 연결되지 않은 상태에서도 완전히 렌더링되어야 합니다. HTML
템플릿은 여러 개 마련하여, 간략 보고/상세 보고, 기술용/경영진용 등 용도에 따라 다른 형식으로 출력할 수도
있습니다.•

PDF 생성:  PDF는 보고서를 배포하거나 증빙자료로 제출할 때 많이 사용되므로, BreachScope는 HTML 보고

Headless  브라우저를  활용하는  방법이  많이  쓰입니다.  예를  들어  Puppeteer(Chromium  기반)나
wkhtmltopdf(WebKit 기반) 도구를 이용하면 복잡한 CSS가 적용된 HTML도 원본과 거의 동일한 레이아웃으
로  PDF를  만들  수  있습니다.  이러한  툴을  오프라인  환경에서  사용하려면  해당  실행  파일(예:
wkhtmltopdf.exe나 headless Chromium)을 번들에 포함해야 합니다. 변환 방식의 장점은 HTML만 잘 만들
어두면 PDF는 비교적 쉽게 얻어진다는 점입니다. 반면 코드 기반 PDF 생성 은 ReportLab (Python)이나 iText
(Java) 같은 라이브러리를 써서 직접 PDF 객체를 생성하는 것으로, 정밀한 제어는 가능하지만 구현 난이도가
높습니다. BreachScope는 유지보수성과 개발 편의를 고려하여 HTML 템플릿 + PDF 변환  방식을 򟻘하는
것이 적절해 보입니다. 이 경우 사용자가 원하면 HTML 보고서를 열람하거나 PDF로 저장할 수 있게 하여 활용
성을 높일 수 있습니다. 실제로 대부분의 포렌식 툴이 HTML 보고서 생성 후 PDF로 export하는 방식을 사용합
니다.
보고서 내용 구성 및 요약:  자동 생성된 보고서는 핵심 정보를 빠짐없이 담되, 가독성을 위해 적절한 요약과 구
조화가  필요합니다.  일반적으로  포렌식  보고서는  요약본과  상세본  두  부분으로  나눌  수  있습니다.
BreachScope가 생성하는 보고서 예시를 들면: 1) 사건 개요 (침해사고 개요와 주요 결과 요약), 2) 공격 타임
라인 개괄 (도식화된 타임라인 이미지 혹은 표로 주요 이벤트 흐름 표시), 3) 식별된 공격 단계별 상세 설명 (초
기 침투, 권한 상승, 데이터 탈취 등으로 구분하여 각 단계에서 어떤 일이 있었고 어떤 증거가 확인되었는지 서
술), 4) 증거 목록 및 세부 분석 (발견된 악성 파일 해시 목록, 의심 프로세스/네트워크 연결 리스트, 주요 로그
이벤트 원문 등), 5) 결론 및 권고사항으로 구성할 수 있습니다. BreachScope는 분석 과정에서 축적한 시나리
오 추론 결과 와 악성 행위 식별  내용을 문장으로 표현하기 위해, 일정 부분 템플릿에 기반한 자연어 생성(NLG)
기법도 사용해야 합니다. 예를 들어 "{{Hostname}}" 시스템에서 {{DateTime}}에 실행된 프로세스 
"{{ProcessName}}"에서 암호 덤프 도구가 탐지되었습니다.  같은 템플릿을 작성해 두고 변수를 채우면,
각 시스템별로 유사한 서술을 자동으로 생성할 수 있습니다. 이런 템플릿 문장은 한국어/영어 등 다국어로도 준
비해 두면 향후 보고서 언어를 변경하기도 수월할 것입니다.
보고서 생성 시 고려사항:  보고서 자동화에서 중요한 점은 증거의 출처와 신뢰도 표기 입니다. BreachScope가
출력하는 내용마다 근거가 되는 로그나 파일의 경로, 이벤트 ID 등을 표시하여, 보고서를 읽는 이가 해당 결론의
근거를 추적할 수 있어야 합니다. 또한 보고서 내에 포함된 모든 증거 데이터(스크린샷, 로그 전문 등)는 사전에
무결성 해시(SHA-256 등)가 계산되어 있어야 하며, 필요 시 보고서에 부록으로 해시 목록을 포함시킵니다.
PDF 메타데이터에는 사건 식별자와 작성 날짜 등을 기록하고, 각 페이지에는 기밀 등급이나 “Forensic Report
– Confidential” 같은 표시를 넣어 문서 관리에도 유의해야 합니다. 마지막으로, HTML/PDF 생성 기능 자체의
보안도 고려해야 하는데, 예를 들어 보고서에 포함된 외부 이미지 링크를 차단하고, JavaScript를 사용하더라
도 보고서 내용 조작에 악용될 수 있는 스크립트는 포함하지 않는 등 안전하게 생성해야 합니다.
오프라인 환경 고려 및 보안 대책
BreachScope는 인터넷에 접속되지 않은 격리된 폐쇄망 환경 에서도 완전한 기능을 제공해야 합니다. 이를 위해 필요한
설계 고려사항 및 보안 대책은 다음과 같습니다:
외부 의존성 없는 동작:  오프라인 환경에서는 클라우드 API나 공개 인텔리전스 피드에 질의할 수 없으므로,
BreachScope의 모든 기능은 로컬 리소스 만으로 구현되어야 합니다. 예를 들어, 최신 위협 정보를 위해 외부
IOC 피드나 VirusTotal을 조회하는 대신, 초기 설치 시 내장된 인텔리전스 DB를 사용하거나 주기적으로 수동
업데이트 패키지를 받아 적용하는 방안을 마련합니다. 소프트웨어 설치 또한 인터넷 없이 가능하도록 오프라인
인스톨러를 제공하고, Velociraptor Offline Collector처럼 실행 바이너리에 필요한 모든 룰셋과 파서가 포함
된 올인원 패키지를 생성하는 기능도 유용합니다. 이러한 자체 포함성(self-contained)은 폐쇄망뿐 아니라 현
장 대응 시에도 편의를 제공합니다.

제공하여 수사 과정의 투명성을 높입니다. BreachScope도 내부적으로 사용자 활동과 자동 분석 활동을 상세
히 기록하고, 필요 시 이를 내보내어 증거로 제출하거나 문제 발생 시 역추적할 수 있어야 합니다.
경량성 및 성능 최적화:  오프라인 환경의 많은 시스템은 사고 대응을 위해 일시적으로 에이전트를 설치하는 것
이므로, BreachScope의 에이전트/수집 모듈은 시스템에 부하를 최소화해야 합니다. Velociraptor 클라이언
트가 idle 시 1% 미만의 CPU만 사용하도록 설계된 것처럼, BreachScope 에이전트도 메모리와 CPU 사용을
줄이고, 필요한 경우 QoS 설정이나 작업량 조절 기능(예: 한꺼번에 디스크를 훑지 않고 조각내어 처리)을 제공
해야 합니다. 또한 대량의 로그를 처리할 때는 효율적인 알고리즘과 인덱싱을 사용하여 분석 시간이 과도하게
길어지지 않도록 해야 합니다. 오프라인 환경에서는 분석 리소스를 추가로 확보하기 어려우므로, 멀티스레딩/병

업데이트 및 확장성:  폐쇄망에 설치된 소프트웨어는 업데이트가 까다롭기 때문에, BreachScope는 출시 시 최
대한 완성도 높게 다양한 포맷과 사례를 커버해야 하고 범용성을 가져야 합니다. 새로운 브라우저 버전이나 운
영체제가 나와도 그 로그를 분석할 수 있어야 하며, 만약 지원하지 않는 포맷이 발견되면 사용자 정의 파서를 추
가할 수 있는 인터페이스(예: 플러그인 구조)를 제공하는 것이 좋습니다. 또한 룰 기반 분석의 경우 시간이 지남
에 따라 공격 기법이 변하므로, 규칙을 주기적으로 보강해줘야 합니다. 인터넷 업데이트가 불가하다면, 예를 들

수동으로 룰 파일을 교체하는 방법이라도 안내해야 합니다. 
환경 격리 및 자기 보호:  최악의 경우, 공격자에 의해 BreachScope 자체가 공격 대상이 되거나 무력화될 가능

나, 보고서 생성 시 출력 내용을 변조하려는 시도가 있을 수 있습니다. 이를 막기 위해 BreachScope 에이전트

호 기능을 탑재할 수 있습니다. 또한 BreachScope 서버/콘솔 자체도 강력한 인증과 암호화를 적용하여, 보고
